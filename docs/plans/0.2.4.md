# Inkwell 0.2.4 plan

Everything compared with Excalidraw and the pen-note apps (OneNote, GoodNotes, Notability,
Xournal++) that was chosen for 0.2.4. Built in this order: each phase is tested in Chrome,
Firefox, WebKit and the iPad profile (plus the Linux app with the virtual pen where input is
involved), committed, and pushed to the website before the next starts. 0.2.4 is tagged when
all phases are in (one app release at the end; the website updates per phase).

Rule for every phase: new page content must work with undo, live sessions, PDF export, the
sidebar thumbnail, search and notebook folders, or the gap is said in the app and here.

## Phase 1 — Gaps in what exists

| | What | How |
|---|---|---|
| 1.1 | Code blocks in undo | Snapshots (`ink.ts` history) include `codes`; add/move/delete/edit are undo steps. |
| 1.2 | Code blocks and Markdown notes in live sessions | Worker relays `codes` and `md` changes like strokes/texts (last write wins per item). |
| 1.3 | Pen ink on Markdown notes | Transparent ink layer over the note (strokes stored on the page, scrolled with the note); pen draws, finger/mouse scroll and type. |
| 1.4 | Markdown notes in PDF export | Render the note to text runs (headings, lists, code) with pdf-lib, plus its ink. |
| 1.5 | Windows pen | Act on the friend's calibration report (raw input section). |

## Phase 2 — Notebook pages

| | What | How |
|---|---|---|
| 2.1 | Continuous pages | Folders whose pages are paper (A4/A3/Letter) can be shown as one vertical scroll of sheets, GoodNotes-style; each sheet is still its own page (undo, export, thumbnails unchanged). |
| 2.2 | Page templates | Backgrounds: Cornell (cue column + summary), music staff, engineering grid, and a custom picture (stored as a blob like pictures). |
| 2.3 | Handwriting search | Recognise each page's ink in the background when idle (on-device reader, cached by stroke ids); search matches it. |
| 2.4 | Links between pages | Text boxes / Markdown `[[Page name]]` link to pages; a folder's table of contents page. |

## Phase 3 — Shapes, Excalidraw-style

| | What | How |
|---|---|---|
| 3.1 | Real shapes | New `shapes` on the page: rectangle, ellipse, diamond, line, arrow; stroke colour/width, fill (none/solid/hachure), dashed/dotted; hold-to-snap makes a shape instead of ink points. Lasso selects them; handles resize. |
| 3.2 | Connected arrows | Arrow ends bind to shapes; moving a shape re-routes its arrows. |
| 3.3 | Arrange | Bring forward/back, group/ungroup, align/distribute, lock — on the lasso selection bar. |
| 3.4 | Snapping | To the page grid and to other objects' edges/centres while moving and drawing shapes. |
| 3.5 | Eyedropper, shortcut sheet | Pick a colour from the page; `?` lists every shortcut. |

## Phase 4 — Sharing and files

| | What | How |
|---|---|---|
| 4.1 | SVG export, copy as image | SVG from the same paths as PDF; selection → PNG on the clipboard. |
| 4.2 | `.excalidraw` open/save | Map Excalidraw elements ↔ Inkwell (freedraw ↔ strokes, shapes ↔ shapes, text ↔ text boxes, images ↔ pictures). |
| 4.3 | Read-only share link | Page encrypted in the browser (key in the link's #fragment, never sent), stored on the Cloudflare Worker; the link opens a viewer. Free tier. |
| 4.4 | Shape library | Save a selection as a reusable stamp; drag stamps in. |

## Phase 5 — Big ones

| | What | How |
|---|---|---|
| 5.1 | Pen textures | Fountain (direction-dependent width), brush, pencil (grain texture); a `style` on strokes, rendered on canvas and approximated in PDF/SVG. |
| 5.2 | Audio linked to ink | Record while writing (MediaRecorder, stored as a blob); each stroke keeps its time; tapping ink plays from that moment; a page timeline. |
| 5.3 | Sync between devices | A synced folder that also works on iPad and Android browsers, which can't open folders on the device: a Google Drive folder through Drive's API (free; a Google OAuth client ID set up once). It is one more `Backend` for `vault-core.ts` (list/read/write/mkdir/remove), so `.inkwell` pages, `.md` notes and attachments sync exactly as notebook folders do. The desktop apps keep a real folder kept in sync by Google Drive for desktop (rclone on Linux), so every device sees the same files. |

## Decisions

- Sync: a synced folder, working on iPad and Android web too → Google Drive API backend (5.3).
- Releases: one 0.2.4 for the apps when everything is in; the website gets each phase as it lands.
