# 0.2.8: opening files, opening PDFs, and a test run on every push

Status: approved in chat ("okay start it ... push and make it 0.2.8"), built unattended 2026-10-30.
Every decision below was made without the owner present, so each is marked **my call**; the owner can
change any of them.

## Why

- Dropping files did not work everywhere (fixed in 0.2.7+), and tablets cannot drag files from the
  file manager at all, so there must be a button that opens any file.
- Importing a big PDF blocks writing until every page is drawn.
- Bugs keep reaching other devices because the checks only run when someone runs them by hand.
- Testers cannot find "Report a problem".

## What is in 0.2.8

1. **Open any file.** One command that opens a file picker for everything Inkwell understands and
   routes each file by what it is. Goals: works on a tablet, never fails silently. Non-goals: a
   file browser, remembering recent files. Anti-goal: guessing wrong and importing a file as the
   wrong kind.
   - **my call:** it sits at the top of the Insert menu, named "Open a file…". It reuses the existing
     importers unchanged; the choice is made by name and, for `.inkw`, by content.
   - **my call:** several files can be chosen at once; each is handled in turn.
   - **my call:** a zip or a folder keeps the existing "import or just look" dialog.
2. **Report a problem in a place people look.** **my call:** an item in the Insert menu's neighbour,
   the notebook menu at the top of the sidebar, as well as About.
3. **PDFs open at once.** Goals: the first page is on screen and writable in well under a second for
   any file, and the rest fills in while writing. Anti-goals: pages in the wrong place, a page that
   keeps growing after the user deleted it, a half-imported page nobody told them about.
   - **my call:** page sizes are read first (instant), so the whole long page is laid out before any
     drawing; pictures are then added at their final positions as they are drawn.
   - **my call:** four pages are drawn at a time (measured 1.3 times faster, identical pixels); the
     resolution stays at 2.67 times so zoomed-in pages stay sharp (half the resolution was faster but
     blurrier, and sharpness is the owner's priority).
   - **my call:** a progress line says "Drawing page n of N" and the import stops quietly if the page
     or its folder is deleted meanwhile. If the app closes mid-way, the pages drawn so far stay.
   - Only the single long page path is progressive. One-page-per-PDF-page and PDFs inside zips keep
     the existing all-at-once path (less common, and they return finished pages to other code).
4. **A test run on every push.** **my call:** a GitHub workflow that runs the lint, type checks,
   the unit checks and the browser tests in Chromium, Firefox and WebKit on every push to `main` and
   every pull request. It does not touch the release workflow. Tests that need private files
   (a real OneNote file) skip themselves when the file is absent.

## Not in 0.2.8, and why

- **PDF to Markdown note** (pdf-oxide): its wasm file is 17.6 MB; adding that to every app and the
  Android package is a size decision the owner should make.
- **Obsidian syntax** (callouts, properties, embeds, tags): saving must never alter what Inkwell does
  not understand; that needs its own careful design and a round-trip test against a real vault.
- **Lazy vault loading:** touches the core of notebook folders; too risky to build unattended.
- **Backlinks panel:** left for the Obsidian design above.

## How it is checked

Each item has a browser test that fails without it; the whole gate (lint, type checks, unit checks,
every browser test) must pass before anything is tagged.
